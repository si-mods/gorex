# MOD-001: OSC 7501 (Program Status Protocol)

Status: built (#19).

GoRex has its own implementation of OSC 7501 (#19). The plan is to move onto libghostty-vt when MyGo has the feature. This status is correct as of 2026-10-27.

## Design

### What OSC 7501 is

OSC 7501 lets a program tell the terminal what the program does. The states are `idle`, `working`, `blocked`, `done` and `error`. A `blocked` program waits for the user, and the kind is `permission`, `question` or `auth`. A report can have a progress value and a message.

Rex uses OSC 7501 to mark finished and blocked sessions in its session picker and on unfocused tab headers. Claude Code and Pi send it.

- Spec, revision 0.4 (2026-10-10): https://gist.github.com/mitchellh/7acae3abd8355c1c00287d67e96c913a (also at https://www.superlogical.com/rex/docs/build/program-status)
- A program sends the query `ESC ] 7501 ; ? ST`, then `CSI c`. A terminal that supports OSC 7501 answers `ESC ] 7501 ; ? ST` first.
- Reports have this form: `ESC ] 7501 ; state=…:kind=…:progress=…:app=…:title=<base64>:msg=<base64> ST`.

### How GoRex does it now

- The session server parses OSC 7501 from the output of each session (`internal/rex/status.go`). It keeps the records for each session and applies the lifetime rules. It answers the query itself, one time.
- `SessionInfo` lists the records (`Statuses`) and the most urgent record (`Status`). Remote hosts get them too.
- The app shows the records on tab headers, pane headers and the palette's pane rows. Tab headers include the tabs of a shown workspace. The sidebar rows of a hidden workspace's tabs also show them. The palette lists the panes that wait for the user first.
- The row of a project and the chip in the title bar show a status that needs the user.
- The app sends a notification for `blocked`, `done` and `error` when the user cannot see the pane.
- The records `done` and `error` clear when the user sees the pane. The server keeps the time at which the user saw the records (`SessionInfo.StatusSeen`, the `seeStatus` op). A record that one client shows as seen is seen on all clients, Rex Go also (`gorex.see_block`). It stays seen after the app restarts.
- An in-place upgrade hands over the records (`sessionState.Statuses` and `StatusSeen` in `upgrade.go`). A restart does not hand them over.
- Antigravity CLI sends `state=blocked` with `msg` `"Approve plan"` at an idle prompt when an artifact exists. GoRex records `done` after work, or `idle` at start.
- The answer to the query has no `:states=` and no `:kinds=`. The spec makes them optional.
- On Windows, the program must also read the answer. The inbox ConPTY turns what the server writes to the console input into input events. It drops an OSC reply on the way.
- The Windows app therefore includes the ConPTY package from Microsoft. The package has `conpty.dll` and `OpenConsole.exe` under the architecture directory (`resources/windows-*`). It passes VT input through to a program in `ENABLE_VIRTUAL_TERMINAL_INPUT` mode.
- `internal/rex/pty_windows.go` uses the packaged ConPTY when the package is next to the executable. If not, it falls back to the inbox API.
- The inbox API still closes and resizes the consoles that a previous build made (`pty.bundled`).

### Why not libghostty-vt

- The terminals of GoRex come from the terminal plugin of MyGo. The plugin includes libghostty-vt.
- GoRex uses the fork `si-mods/mygo`. It is a v0.7.4 pseudo-version, set with `replace` in `go.mod`. The fork pins Ghostty commit `108cacb` (2026-11-11, the tag `vt-1.0.1`: libghostty-vt 1.0.1).
- The fork pinned `dc8f599` (2026-11-01) before. MyGo v0.6.2 and v0.7.1 pinned `befcdfd` (2026-10-03).
- libghostty-vt added OSC 7501 after `befcdfd` and before `dc8f599`. The changes are ghostty-org/ghostty#14560 (2026-10-06), #14630 (revision 0.4, 2026-10-10) and #14793 (stricter ids, 2026-10-21).
- libghostty-vt keeps no records itself. It answers the query only when the embedder sets its effect.
- An upgrade of the library alone is not sufficient. MyGo must also set the effect and hand the reports to Go. The terminal plugin of the fork does not do this yet.

### When MyGo has it

1. Upgrade MyGo.
2. Take the reports from libghostty-vt instead of the parser in `status.go`. Do this in the headless terminal of the session server (`session.vt`). Keep the records and the lifetime rules there.
3. Keep exactly one answer for each query. Either the terminal of the server answers or the terminals of the windows answer. Do not use both. Several windows can show one session (see the reply filtering in `internal/rex/session.go`).
4. Run `internal/rex/status_test.go` again against the new path.
