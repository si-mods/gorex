# OSC 7501 (Program Status Protocol)

Status as of 2026-10-27: **supported by GoRex's own implementation (#19).
To move onto libghostty-vt once MyGo has it.**

## What it is

OSC 7501 lets a program tell the terminal what it is doing: `idle`,
`working`, `blocked` (on the user: `permission`, `question` or `auth`),
`done` or `error`, with an optional progress and message. Rex uses it to
mark finished and blocked sessions in its session picker and on unfocused
tab headers. Claude Code and Pi send it.

- Spec, revision 0.4 (2026-10-10): https://gist.github.com/mitchellh/7acae3abd8355c1c00287d67e96c913a
  (also at https://www.superlogical.com/rex/docs/build/program-status)
- A program asks with `ESC ] 7501 ; ? ST`, then `CSI c`. A terminal that
  supports it answers `ESC ] 7501 ; ? ST` first. Reports are
  `ESC ] 7501 ; state=…:kind=…:progress=…:app=…:title=<base64>:msg=<base64> ST`.

## How GoRex does it now

- The session server parses OSC 7501 from each session's output
  (`internal/rex/status.go`), keeps the records per session, applies the
  lifetime rules, and answers the query itself, once.
- `SessionInfo` lists the records (`Statuses`) and the most urgent one
  (`Status`), so remote hosts get them too.
- The app shows them on tab headers, pane headers and the palette's pane
  rows (panes waiting for the user first), and notifies `blocked`, `done`
  and `error` out of sight. `done` and `error` clear once the pane is seen.
- Not handed over across a server upgrade; no `:states=`/`:kinds=` in the
  query's answer (optional in the spec).

## Why not libghostty-vt

- GoRex's terminals come from MyGo's terminal plugin, which bundles
  libghostty-vt. MyGo v0.6.2 (what GoRex uses) and v0.7.1 (the latest) both
  pin Ghostty commit `befcdfd` (2026-10-03).
- libghostty-vt added OSC 7501 after that commit:
  ghostty-org/ghostty#14560 (2026-10-06), #14630 (revision 0.4,
  2026-10-10) and #14793 (stricter ids, 2026-10-21).
- libghostty-vt keeps no records itself, and answers the query only when
  the embedder sets its effect. Upgrading the library alone is not enough:
  MyGo must also set the effect and hand the reports to Go.

## When MyGo has it

1. Upgrade MyGo.
2. Take the reports from libghostty-vt instead of `status.go`'s parser, in
   the session server's headless terminal (`session.vt`), and keep the
   records and lifetime rules there.
3. Keep exactly one answer per query: either the server's terminal answers
   or the windows' do, not both (several windows may show one session; see
   the reply filtering in `internal/rex/session.go`).
4. Re-run `internal/rex/status_test.go` against the new path.
